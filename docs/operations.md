# Резервные копии и диагностика

## Подготовка

Выполните `npm run setup`: в `.env.local` добавится отдельный случайный
`BACKUP_ENCRYPTION_KEY` (32 байта в hex), прежние настройки сохранятся.
Сохраните этот ключ и настройки приложения в защищённом месте отдельно от архивов
и компьютера. Дамп не содержит `.env.local`. Без ключа архив не расшифровать;
прежний `BETTER_AUTH_SECRET` нужен для действующих сессий и личных ссылок.

Нужны `pg_dump` и `pg_restore` PostgreSQL 18. Встроенный npm-сервер их не содержит.
На Windows x64 выполните `npm run db:tools`: команда загрузит официальный архив
EDB 18.6-5, связанный со [страницы PostgreSQL](https://www.postgresql.org/download/windows/),
проверит закреплённый SHA-256 и извлечёт только клиенты и DLL в
`.local/postgres-tools/bin`. Загрузка около 385 МБ; архив затем удаляется.
Глобальные PATH, службы и сервер не меняются. Перед обновлением утилит завершите
операции копирования. При прерванной загрузке удалите файл
`.local/postgres-tools/postgresql-18.6-5.zip` и повторите команду.

На Linux/macOS установите PostgreSQL 18 clients из доверенного пакетного менеджера.
При необходимости задайте `PG_BIN_DIR` — каталог обеих программ. Без него
используется PATH; Windows автоматически находит каталог выше.
[Инструкция Ubuntu](https://www.postgresql.org/download/linux/ubuntu/).
CI устанавливает клиенты 18 из подписанного репозитория PostgreSQL.

Подключение берётся из `DATABASE_URL`, TLS — из `DATABASE_SSL`. Для этих команд URL
не должен содержать дополнительных параметров, имя базы — только латинские буквы,
цифры, `_` и `-`. Унаследованные `PG*` не могут перенаправить соединение или ослабить
TLS. Пароль передаётся через временный pgpass в личном каталоге, а не через аргументы
или `PGPASSWORD`. Права на Unix — 0700/0600; Windows также зависит от ACL профиля.

## Копия с проверкой восстановления

```sh
npm run db:backup
npm run db:verify-backup -- .local/backups/имя.slotlybackup
```

Первая команда создаёт архив в `.local/backups` и сразу проверяет восстановление.
Вторая повторяет проверку указанного файла. Копирование не изменяет рабочую базу:
`pg_dump -Fc` и манифест числа строк используют один экспортированный снимок
транзакции `REPEATABLE READ`. Записи, появившиеся после взятия снимка, попадут в
следующую копию; параллельные изменения не нарушают согласованность текущей.

Дамп включает схему, функции, ограничения, аккаунты, встречи, историю, проверки
гостей, очередь и миграции. Роли кластера, конфигурация PostgreSQL, JSON-письма и
переменные окружения сохраняются отдельно. Это логический дамп, не point-in-time recovery.

Дамп и манифест шифруются потоком AES-256-GCM с новым nonce. Заголовок версии
аутентифицируется как AAD, тег находится в конце. Открытый дамп на диск не пишется.
Завершённый файл публикуется атомарно после успешного выхода `pg_dump`, существующий
архив не заменяется. Незавершённые `.partial` не считаются копиями.

Проверка делает личный зашифрованный снимок файла во временном каталоге и полностью
проверяет GCM-тег **до SQL-восстановления**: GCM способен выдавать байты до финальной
аутентификации. После этого вторая расшифровка передаётся в `pg_restore`.
Неверный ключ или повреждённый файл не достигают создания базы и выполнения SQL.

Восстановление идёт в новую случайную `slotly_restore_<UUID>` одной транзакцией,
с остановкой при первой ошибке. Не используются `--create`/`--clean`, которые могли
бы задействовать исходное имя базы из архива. Проверяются набор таблиц, число строк,
журнал миграций и валидность ограничений. Удаляется только база, созданная этой
операцией. Веб-сервер и обработчик к ней не подключаются. Клиентские команды
ограничены десятью минутами; их предупреждения/ошибки прерывают операцию, сырые
stderr и реквизиты не выводятся.

После успеха рядом с архивом появляется `.verified.json` с SHA-256 зашифрованного
файла и временем проверки. Это локальный эксплуатационный отчёт, не независимая
аттестация. Если создание прошло, а восстановление не удалось, архив сохраняется,
но команда завершится с ошибкой.

## Реальное восстановление

```sh
npm run db:restore-backup -- .local/backups/имя.slotlybackup slotly_recovered_20261101
```

Допускается только **новое** имя `slotly_recovered_*`, отличное от исходного.
Существующая база не очищается и не заменяется. При неудаче созданная этой попыткой
база удаляется; при успешной сверке новая база сохраняется. Подключение приложения
не переключается автоматически. Служебное соединение использует базу `postgres`,
поэтому восстановление работает и при утрате оригинальной базы в живом кластере.

При аварии остановите веб-процесс и обработчик, сохраните повреждённую базу для
разбора, восстановите архив в новое имя, проверьте данные и необходимые секреты.
Затем отдельно измените `DATABASE_URL`, проверьте миграции и запустите приложение.
Между временем копии и аварией возможны новые записи. Копия очереди тоже отражает
старое состояние доставки: перед запуском внешней почты учитывайте идемпотентность.

Оператору нужны чтение данных, создание/удаление собственных проверочных баз и
права на восстановление схемы и расширений. Для публичной среды это отдельный
доступ, не роль веб-приложения. Восстанавливайте только доверенные архивы: дамп
может содержать SQL исходного администратора.

## Диагностика

```sh
npm run ops:check
```

JSON не содержит адресов участников и реквизитов подключения. Проверяются БД,
временные метки журнала миграций относительно кода, очередь, ошибки доставки,
просроченные аренды и ожидание дольше пяти минут. Это не полный DDL-diff.
Отдельно показываются расширенные права текущей роли; локально они ожидаемы,
перед пилотом нужна отдельная роль приложения.

У последнего архива проверяются возраст до 24 часов и SHA-256 относительно отчёта
восстановления. Для этого файл читается целиком; большие архивы требуют времени.
Коды выхода: 0 — проверки пройдены, 2 — требуется внимание, 1 — команда не завершена.
Причины включают `BACKUP_MISSING`, `BACKUP_NOT_VERIFIED`, `BACKUP_OLDER_THAN_24H`,
`DELIVERY_FAILED`, `EXPIRED_LEASES`, `QUEUE_DELAYED`, `MIGRATIONS_PENDING`.

Команды запускаются вручную. График, внешние оповещения, хранение вне компьютера
и сроки удаления пока не настроены. Для публичного пилота нужны независимое
хранилище, отдельно сохранённые ключи, регулярные проверки и выбранные RPO/RTO.
Провайдеры и платные услуги не подключались.

Тесты покрывают шифрование и повреждения, другой ключ, ошибку producer, отказ
перезаписи, восстановление и неизменность источника, параллельную запись, отсутствие
оригинальной базы, существующую цель, очистку временных ресурсов и диагностику.
