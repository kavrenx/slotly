# Техническая передача к этапу дизайна

Цель текущей сборки — рабочий **локальный MVP персональной записи**, который можно
проверять и дорабатывать визуально без подключения внешних сервисов. Публикация
исходников на GitHub и успешный local-check не означают публичный запуск.

## Рабочие сценарии

- Организатор: аккаунт, подтверждение почты, вход и восстановление доступа.
- Одно общее расписание, исключения, несколько страниц записи и их состояния.
- Участник: свободный слот, OTP без аккаунта, подтверждённая запись.
- Отмена и перенос с сохранением условий, общей занятостью и неизменяемой историей.
- Кабинет, фильтры и списки встреч, уведомления обоим участникам.
- PostgreSQL ограничивает пересечения, роли разделены; CSP и ограничения запросов
  проверяются на сборке и в тестах.

Данные этих экранов берутся из локальной PostgreSQL. Они не заменены декоративными
массивами. Демонстрация на лендинге остаётся отдельным иллюстративным примером.

## Адаптеры и отложенные подключения

| Участок | Сейчас | Подключается после дизайна |
| --- | --- | --- |
| Почта | Локальный просмотрщик; готов SMTP-транспорт | Провайдер, домен отправителя, реальные проверки доставки и обработки отказов |
| База | Локальная PostgreSQL, runtime/migration роли | Выбранный сервер/managed PostgreSQL, его TLS и выдача прав |
| Копии | Локальные зашифрованные архивы с проверкой восстановления | Независимое удалённое хранилище, согласованные RPO/RTO и сроки удаления |
| Наблюдение | Диагностика и файловый журнал событий | Внешний мониторинг, канал оповещений и контроль остановки worker |
| Обслуживание | Локальный периодический процесс | Планировщик/служба выбранного хостинга и нужный размер порций |
| Входящие IP | Loopback; готова настройка одного доверенного заголовка | Сетевая изоляция и перезаписывающий заголовок реального прокси |
| Публикация | Localhost и исходники GitHub | Домен, HTTPS, развёртывание и проверка боевого окружения |
| Постоянные персональные данные | История сохраняется; просроченные служебные записи очищаются | Утверждение сроков хранения, механизм удаления/обезличивания и юридические тексты |

Последняя строка — явно оставленная работа перед публичным сбором данных,
а не готовая функция удаления. Очистка кодов и сессий её не заменяет.
Заглушки внешних подключений не выдают успех и не отправляют данные наружу.
`release:check` отдельно показывает `publicLaunch.ready=false` и список таких работ.

## Локальное обслуживание

```sh
npm run maintenance:check
npm run maintenance:run
npm run ops:once
npm run ops:local
npm run release:check
```

Первые две команды соответственно показывают число устаревших служебных строк и
удаляют до 100 строк из каждой разрешённой таблицы одной транзакцией. Сохраняется
дополнительный день после окончания кодов, сессий и окон rate limit. Источник
времени — PostgreSQL. Удаляются только `guest_challenges`, `guest_rate_limits`,
`mail_delivery_limits`, `auth_sessions`, `auth_verifications`, `auth_rate_limits`.
Аккаунты, встречи, занятость, история и очередь доставки не очищаются.

Очистка имеет транзакционную advisory-блокировку и SKIP LOCKED. Обновляемая другим
процессом сессия пропускается; при ошибке позднего шага ранние удаления откатываются.
Preview не меняет строки. При большом объёме требуются отдельная оценка индексов,
сроков хранения и размеров порций; это не безлимитная массовая очистка.

`ops:local` выполняет цикл диагностики раз в минуту, очистку — раз в 15 минут.
Раз в 15 минут проверяется необходимость новой копии: если последняя отсутствует,
не проверена или старше суток, вызывается отдельная команда копирования с проверкой
восстановления. После неудачи повтор не чаще 15 минут. Ключ и администратор БД
загружаются только дочерним backup CLI; web и maintenance работают runtime-ролью.
Ничего не скачивается и не устанавливается автоматически.

Сервисная session-блокировка допускает один operations-worker на базу.
`ops:once` выполняет один цикл и возвращает 0 при успехе, 2 при проблемах, 1 при
незавершённой команде. Пока процесс не запущен, компьютер выключен или спит,
периодические задачи не выполняются. Это локальный адаптер планировщика.

События записываются в `.local/operations/events-YYYY-MM-DD.jsonl`. Контакты,
токены, URL подключения, тексты ошибок и содержимое писем туда не попадают.
Неизменившаяся проблема не записывается повторно в рамках одного запуска worker;
успешный повтор после сбоя даёт recovery-событие. Файлы журнала, локальные письма
и резервные копии не удаляются этим обслуживанием и остаются вне Git.

`OperationsSink` — точка замены локального журнала будущим внешним адаптером.
Удалённое хранилище и мониторинг сейчас не имитируются успешными сетевыми вызовами.

## Проверка перед визуальной работой

`lint`, `typecheck`, unit и интеграционные тесты, production build,
`security:check`, `ops:check`, `release:check`. Последняя команда проверяет локальные
APP_URL/БД/почту, миграции, права, очередь и копию. Она не заменяет полный проход
пользовательских сценариев или проверку настоящей доставки после подключения SMTP.

На этапе дизайна можно менять композицию, компоненты, типографику и состояния
экранов, сохраняя серверные контракты и источники данных. Порядок экранов и
визуальное направление согласуются с владельцем продукта перед переделкой.
