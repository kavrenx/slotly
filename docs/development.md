# Окружение и локальная разработка

## Требования и процессы

Node.js 24.x, npm 11.x. Версии зависимостей и lockfile фиксированы. Embedded
PostgreSQL — помощник для разработки на поддерживаемых Windows, macOS и Linux;
для собственного PostgreSQL он не нужен. База слушает только `127.0.0.1`, использует
SCRAM, UTF-8 и UTC. Каталог данных — `.local/postgres`.

Приложение, база и просмотрщик почты запускаются тремя командами в отдельных
терминалах, как описано в [README](../README.md). Обработчик уведомлений запускается
вместе с `dev` и `start`. Остановка одного дочернего процесса останавливает другой.

На Windows перед `npm ci` останавливайте локальное приложение и PostgreSQL:
загруженные нативные модули и бинарники нельзя заменить. Для обычной правки исходников
переустановка зависимостей не нужна. При нехватке памяти запускайте проверки
последовательно, с одним Vitest worker, и временно останавливайте веб-сервер.

## Окружение

`.env.example` содержит образец, `npm run setup` создаёт `.env.local` со случайными
паролем и секретом. Повторный setup не перезаписывает существующие значения.
Никакая переменная не имеет префикса `NEXT_PUBLIC_`.

| Переменная | Назначение |
| --- | --- |
| `APP_URL` | HTTP(S) origin без пути и параметров |
| `DATABASE_URL` | PostgreSQL URL с пользователем, паролем и именем базы |
| `DATABASE_SSL` | `disable` для локальной базы, `verify-full` для проверяемого TLS |
| `BETTER_AUTH_SECRET` | Случайный секрет не короче 32 символов |
| `MAIL_TRANSPORT` | Сейчас только `local`, допускается только loopback APP_URL |
| `BACKUP_ENCRYPTION_KEY` | Отдельный ключ 32 байта в hex для резервных копий |
| `PG_BIN_DIR` | Необязательный каталог клиентских `pg_dump` и `pg_restore` версии 18 |

`NODE_ENV` задают Next.js, Vitest и команды запуска; не записывайте его в `.env.local`.
Загрузка следует порядку `.env*` Next.js; переменные процесса имеют приоритет.
Интеграции дополнительно загружают `.env.local`, который Next.js обычно пропускает
в test-режиме. Ошибки конфигурации не выводят значения секретов.

Символы пароля в URL должны быть percent-encoded. Параметры `ssl*` в URL запрещены:
TLS настраивается только `DATABASE_SSL`, чтобы не ослабить проверку незаметно.
Публичный production требует HTTPS и проверяемого TLS к внешней базе. Локальная
готовая сборка допускает HTTP на loopback и локальную БД без TLS.

Ротация `BETTER_AUTH_SECRET` отзывает сессии и личные ссылки встреч; это не способ
исправления обычной локальной ошибки. Не меняйте пароль уже созданного кластера
редактированием `.env.local`: это не меняет учётные данные внутри PostgreSQL.

## Собственный PostgreSQL и миграции

Укажите подключение в `.env.local`, пропустите `db:local`, выполните миграции и
`db:check`. Приложению нужны PostgreSQL и расширение `btree_gist`. Миграционному
пользователю нужны права на создание схемы, расширения и функций. Для интеграций
нужно право `CREATE DATABASE` на **локальном** сервере и клиентские утилиты
PostgreSQL 18. На Windows x64 их готовит `npm run db:tools`.

```sh
npm run env:check
npm run db:check
npm run db:migrate
npm run db:generate
```

Схема приложения — `slotly`, журнал — `drizzle.__drizzle_migrations`. В репозиторий
входят SQL и метаданные Drizzle. `generate` не видит пользовательские SQL-функции,
exclusion constraints и constraint triggers: такие изменения оформляются custom
миграциями. После публикации предыдущие миграции не переписываются.

```sh
npm exec drizzle-kit generate -- --custom --name=change_name
```

Не используйте `drizzle-kit push` для публичного окружения. В развёртывании миграции
выполняются отдельно один раз, а не при старте каждого веб-процесса. `build` не
нуждается в подключении к БД; `db:check` проверяет настоящее подключение и UTC.

## Почта и очередь

`npm run mail:local` открывает только loopback-порт 8025. JSON-письма хранятся в
`.local/mail`, наружу не отправляются. Это разработческий просмотрщик с секретными
ссылками и кодами: не выставляйте его в интернет.

```sh
npm run notifications:status
npm run notifications:once
npm run notifications:work
npm run notifications:retry
```

Последняя команда явно возвращает все терминальные ошибки доставки в очередь.
Подробности повторов, аренды и идемпотентности — в [notifications.md](notifications.md).

## Зависимости и публикация

`npm audit --omit=dev` при подготовке исходников не нашёл уязвимостей рабочих
зависимостей. Полный аудит сообщает о moderate advisory `minimatch` внутри цепочки
TypeScript ESLint. Принудительный `audit fix --force` не применялся: он предлагает
смену несовместимых инструментов. Перед следующей публикацией выполните аудит заново.

ESLint 10 настроен через совместимые плагины напрямую: цепочка `eslint-config-next`
ожидает другую major-версию ESLint. Override esbuild 0.28.2 согласует инструменты
Drizzle/Vite. `drizzle-kit studio` и esbuild serve не используются.

GitHub Actions использует read-only разрешения, закреплённые SHA действий и отдельный
PostgreSQL 18. Рабочие пароли, база и почта не загружаются как артефакты CI.
В `.gitignore` входят `.env*` (кроме образца), `.local`, зависимости, сборки,
отчёты, журналы и дампы. `next-env.d.ts` генерируется Next.js и также игнорируется.

Добавлены зашифрованные копии, проверка восстановления и диагностика —
[подробности](operations.md). Перед публичным пилотом нужны внешний почтовый
транспорт и его доменная настройка, график независимых копий, внешние оповещения,
отдельные runtime/migration роли PostgreSQL и проверка CSP итогового приложения.
Публикация исходников на GitHub не выполняет эти работы автоматически.
