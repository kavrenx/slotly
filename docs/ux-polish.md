# UX/UI polish — последовательность работ

Палитра, маршруты, серверные правила записи, снимки условий, транзакции и защита
OTP сохраняются. Каждый пакет — отдельный проверяемый результат.

## Пакет 1 — публичная запись (готов)

- [x] Сетка слотов, ограниченная аккуратная прокрутка, состояния и обновление.
- [x] Компактный выбор с датой, временем, зоной и понятной кнопкой продолжения.
- [x] Единые компактные этапы «Время → Контакты → Подтверждение».
- [x] Контакты, ошибки, загрузка и возврат без потери исправимых данных.
- [x] Вставка шестизначного кода, таймер и повторная отправка по прежним лимитам.
- [x] Экран успеха с основной информацией и второстепенным номером записи.
- [x] Сквозная проверка записи, отмены, переноса и мобильных экранов.

Общие `BookingSteps` и `MeetingSummary` используются на всех этапах публичной
записи. Форматирование времени учитывает переход через полночь/год и разные
UTC-смещения начала и окончания встречи. `MeetingTime` в управлении записью
сохранён. Контакты хранятся только в памяти текущей страницы и очищаются после
успешного подтверждения; пароли, коды и ссылки не записываются в браузерное
хранилище. Поле кода принимает вставку шести цифр с пробелами без обрезания.
Клиентские блокировки Enter соответствуют состояниям кнопок; ограничения и
идемпотентность по-прежнему обеспечиваются сервером.

Проверено 1 ноября 2026: TypeScript, ESLint, 250 модульных и 196 интеграционных
тестов, production build, CSP/nonce и защитные заголовки пяти страниц. Модульные
тесты дополнены сценариями повторного часа DST, смены даты/года, дальней зоны
и вставки OTP. В Chromium проверены ширины 320/390/1280/1600, прокрутка 35 слотов,
пустой день, выбор/сброс/обновление, смена зоны, клавиатурный фокус и reduced motion.
На отдельной БД с отдельной локальной почтой пройдены контакты → неверный код →
вставка кода → подтверждение, повторная отправка и отклонение предыдущего кода,
перенос, отмена и история. Дополнительно проверены создание/публикация страницы,
кабинет и расписание. Реальные устройства Safari/Firefox отдельно не проверялись.
HTML-письма в этом пакете не изменялись; их визуальная проверка относится к пакету 2.

### Письма

`MailPresentation` содержит структурированный текст; общий шаблон экранирует
все значения. Произвольный HTML и внешние картинки не принимаются. Разметка
на таблицах со встроенными стилями, SMTP отправляет multipart/alternative.
Локальная почта показывает ту же оформленную часть и раскрываемую текстовую
версию. Старые локальные письма без presentation по-прежнему читаются.
Поддержаны OTP, подтверждение почты, восстановление доступа, создание/перенос/
отмена встречи для обоих получателей. Время берётся из соответствующего события,
включает зону и оба смещения при DST; данные не подменяются текущей страницей.
Защищённые ссылки формируются прежним механизмом. HTML-кнопки допускают только
известные маршруты того же origin; публичный production требует HTTPS через
существующую проверку окружения. Новых провайдеров и сетевых ресурсов нет.

### Календарь

На экране успешной подтверждённой записи скачивается `.ics`: UTC DTSTART/DTEND,
стабильный UID, название, исходное описание, место и имя организатора. Правила
экранирования текста и сворачивания строк по 75 UTF-8 байтам следуют
[RFC 5545](https://datatracker.ietf.org/doc/html/rfc5545#section-3.1).
Email участника, OTP и management token не включаются. Описание receipt берётся
из уже сохранённого quote, в том числе при идемпотентном повторе после редактирования
страницы; новой миграции и постоянного поля bookings для этого не требуется.
Экспорт доступен на экране успеха, не расширен на управление старыми встречами.
Это отдельная копия, не подписка: перенос/отмена не обновляют скачанный файл,
и интерфейс сообщает об этом до скачивания. Для cancelled receipt кнопки нет.

### Редактор, карточки и расписание

Пресеты длительности/шага дополняют собственное значение. `MinuteRuleField`
меняет только представление целых минут. Остаток сохраняется явно, поэтому
121 мин → 2 ч + 1 мин → 0 дн + 121 мин не округляется. Значение 0, пределы,
кратность, версия и серверная валидация остаются прежними. Сводка отражает текущие
поля и помечает несохранённые изменения; публикация использует сохранённую версию.
Карточки двухколоночные на широком экране, одноколоночные на узком, с реальными
действиями по состоянию; архив раскрывается отдельно.

Обзор рабочей недели отражает сохранённые или явно помеченные текущие поля,
с несколькими интервалами, перерывами и выходными. Неверные/пересекающиеся
интервалы показывают подсказку вместо ложной полосы. Это не расчёт свободных
слотов. Редактор сохранён, список исключений имеет ограниченную прокрутку с
местом для клавиатурного фокуса. На телефоне обзор компактнее, поля крупнее.

### Проверка и ограничения

Итоговые проверки: TypeScript, ESLint, 271 модульный и 197 интеграционных тестов,
production build, CSP/nonce и защитные заголовки. После дополнения проверок
HTML писем отдельно повторены identity + notifications (47 тестов).
Добавлены проверки MIME HTML/plain, экранирования и ссылок, UTC/DST/Unicode/
инъекции календарных свойств, сохранённого описания, всех значений 0…43200 в трёх
единицах и корректности рабочего обзора.

В Chromium проверены создание/сохранение/публикация/пауза/возобновление страницы,
сохранение 121 минуты и 30 дней после reload, состояния и архив карточек,
перерывы, ошибка пересечения, добавление/изменение/удаление и сохранение семи
особых дат; мобильные экраны. Пройдены OTP → запись → реальное скачивание и
проверка `.ics` → перенос → отмена; фактически сформированные письма проверены
в отдельной локальной почте. Данные теста, БД и почта изолированы от пользователя.

Реальные Outlook/Gmail/Apple Mail, импорт в внешние календарные приложения и
устройства Safari/Firefox отдельно не проверялись. Соответствие формату и
MIME/HTML проверены автоматически и в Chromium, без обещания пиксельного
совпадения всех почтовых клиентов. SMTP-провайдер, домен и публичный пилот
остаются последующей работой; текущий локальный режим сохранён.

Для каждого пакета: типы, линтер, подходящие модульные/интеграционные тесты,
production build, браузер, мобильная ширина, клавиатура и reduced motion.
Незатронутые экраны и ограничения проверяются на регрессию. Публичный пилот и
подключение провайдеров остаются отдельной работой после дизайна.
